Product Catalog Custom Module Specification (Drupal 11)

Overview

This specification outlines a Drupal 11 custom module for a Product Catalog system, designed to cover a comprehensive set of Drupal site-building and development concepts. The module provides a functional product listing system with features for both site admins and end users, incorporating content types, taxonomy, views, custom forms, AJAX, modals, and advanced Drupal APIs. The goal is to create a practical, hands-on project that exercises all learned topics, including hooks, services, caching, and multilingual support.

Content Structures & Core Features

The module leverages Drupal core and contributed modules to create a robust content structure:

  • Product Content Type: A custom content type with fields:
    • Title (product name)
    • Body/Description (long text, WYSIWYG editor)
    • Price (decimal field)
    • Product Images (Media field, multiple images via Media module)
    • Category (entity reference to Product Category taxonomy)
    • Features (Paragraphs field for flexible content)
    • Availability (boolean/list field for in-stock/backorder)
  • Product Categories (Taxonomy): A "Product Category" vocabulary for classifying products (e.g., Electronics, Furniture).
  • Comments (Reviews): Enable core Comment module with a "Product Review" comment type for user reviews on products.
  • Media and Images: Use core Media module for product images, integrated into the Product content type.
  • Paragraphs Module: Create a "Product Feature" Paragraph type for flexible product specifications.
  • Layout Builder: Enable Layout Builder for customizable product page layouts.
  • Views: Create a page view at /products for listing products with pagination and filters, plus a "Latest Products" block.
  • Menus: Add menu links for the product listing page and admin pages in the Main Navigation or Admin menu.
  • Multilingual Support: Enable Language, Content Translation, and Configuration Translation modules for translatable products and taxonomy terms.
  • Contact Form: Use core Contact module for site-wide contact, with a custom inquiry form for products (detailed below).
  • User Roles & Permissions: Define a "Product Manager" role with permissions for managing products and inquiries.
  • Configuration Management: Export configurations (content types, views, etc.) to YAML for reproducibility using Drush config-export/import.

Custom Pages and Navigation

The module defines custom pages using Drupal's routing and controller system:

  • Product Dashboard: An admin page at /admin/products/dashboard for Product Managers, displaying product statistics (e.g., total products, recent products). Uses EntityQuery and a custom controller.
  • Product Import Page: A page at /admin/products/import with a form for uploading CSV files to import products.
  • Other Routes: Potential routes like /products.json for JSON output or a confirmation form for deleting products.

Routes are defined in the module's routing YAML, with permissions and CSRF token requirements, covering Menu API, Custom Page creation, and Permissions.

Blocks and Forms (Frontend Features)

  • Latest Products Block: A custom block plugin (src/Plugin/Block/LatestProductsBlock.php) displaying recent products using EntityQuery. Configurable via block settings form.
  • Product Inquiry Form Block: A block with a form for users to submit inquiries about specific products, rendered on product pages.
  • Confirm Action Form: A confirmation form at /admin/products/delete-all for deleting all products, accessible only to admins.

These cover Block API, Form API, and rendering forms in blocks.

Hooks and Event Subscribers

The module implements various hooks and event subscribers:

  • Hooks:
    • hook_form_alter(): Modify the Product node edit form (e.g., make Price field required).
    • hook_node_insert(): Enqueue notifications for new products.
    • hook_node_update(): Invalidate cache or update data on product updates.
    • hook_node_delete(): Clean up related data on product deletion.
    • hook_views_data(): Expose custom inquiry table to Views.
    • hook_cron(): Process periodic tasks like sending daily reports.
    • hook_permission(): Define custom permissions.
    • hook_help(): Provide help text for the module.
  • Event Subscribers:
    • Subscribe to core events (e.g., node save) and a custom ProductLowStockEvent to send alerts.
    • Defined in src/EventSubscriber with services YAML tagging.

This covers Hook System, Event Dispatcher, and Event Subscriber topics, contrasting procedural hooks with OOP event subscribers.

Interactive Features (AJAX and Modals)

  • AJAX Form Submission: Product Inquiry Form submits via AJAX, displaying a thank-you message without page reload.
  • Modal Dialog: "Quick View" modal for product details, using Drupal's AJAX dialog API.
  • Dynamic Product Filter: AJAX-powered filter on the product listing page (using Views AJAX or custom JS).
  • Autocomplete Field: Autocomplete field for product names in the inquiry form, using Drupal's autocomplete route.

These features use Drupal's AJAX framework and Dialog API, with custom JS/CSS libraries defined in the module.

Scheduled and Bulk Operations

  • Cron Tasks: Implement hook_cron() for tasks like sending daily product digests or clearing old inquiries.
  • Queue Worker: Use Queue API for deferred tasks like sending product notification emails.
  • Batch Import: Product CSV import via a batch process to handle large imports without timeouts.
  • File Handling: Manage CSV uploads and exports using Drupal's File API.

These cover Cron, Queue, Batch, and File Handling APIs, ensuring efficient processing of heavy tasks.

Data Storage and Integration

  • Custom Table: A product_inquiry table for storing inquiries, defined in hook_schema() and managed via Database API.
  • Views Integration: Expose the inquiry table to Views via hook_views_data().
  • Entity Queries: Use EntityQuery for efficient content retrieval (e.g., fetching recent products).
  • Web Services: Leverage Drupal's JSON:API for exposing products as JSON, with potential for custom REST endpoints.

Performance and Caching

  • Render Cache: Apply cache tags (e.g., node_list, node:product) to blocks and pages.
  • Efficient Queries: Use EntityQuery and database indexes for performance.
  • Cache API: Cache expensive computations (e.g., product counts) if needed.

These ensure the module integrates with Drupal's caching system for optimal performance.

Multilingual Support and Translations

  • User Interface Strings: Wrap all strings in t() for localization.
  • Configuration Translation: Mark config settings as translatable in schema.
  • Content Translation: Enable translation for Product nodes and taxonomy terms.

Tested with a second language (e.g., Spanish) to ensure multilingual compatibility.

Module Configuration and Settings

  • Settings Form: A ConfigFormBase form at /admin/config/product-catalog for settings like notification email or stock thresholds.
  • State API: Store runtime values like last cron run timestamp.
  • Default Configuration: Optionally include default configs (e.g., views) in config/install.

Best Practices and Final Notes

  • Coding Standards: Follow Drupal coding standards with proper directory structure and docblocks.
  • Security: Validate inputs, use Twig for output, and enforce permissions.
  • Testing: Test features with different roles, cron runs, and multilingual setups.
  • Extensibility: Design for future enhancements (e.g., Drupal Commerce integration).

The module covers all learned Drupal concepts, providing a practical, step-by-step implementation guide. Happy coding!
